# Deploying Mdawra (Supabase + Render + Vercel)

**Live deployment**

| Piece | URL |
| --- | --- |
| Customer site | https://mdawra.vercel.app |
| Admin panel | https://mdawra.vercel.app/admin/login |
| API | https://mdawra-api.onrender.com (`/api/health`) |
| Database | Supabase project `svyywyoknpocdksdbheh` (ap-northeast-1) |

The Render service auto-deploys on pushes to `devin/mdawra-platform`. Two free-tier limits apply:
the API sleeps after ~15 minutes idle (first request then takes ~50s), and it has no persistent disk,
so images uploaded through the admin panel are lost on redeploy — attach a Render disk (see below)
or move `mediaService` to Supabase Storage.

The steps below reproduce that setup from scratch.

Three pieces: Postgres on **Supabase**, the Express API on **Render**, the React site on **Vercel**.
Total time ~20 minutes. Everything below is copy/paste.

---

## 1. Database — Supabase

1. Create a project at https://supabase.com/dashboard (pick a region close to Kuwait, e.g. `eu-central-1`).
2. Project Settings → **Database** → *Connection string* → **URI**, and copy the **Session pooler** URI
   (port `5432` — the transaction pooler on `6543` cannot run Prisma migrations).
3. Replace `[YOUR-PASSWORD]` with the database password you set, and keep the string safe:

   ```
   postgresql://postgres.xxxxxxxx:PASSWORD@aws-0-eu-central-1.pooler.supabase.com:5432/postgres
   ```

No SQL to run by hand — Prisma creates the schema during the Render build.

---

## 2. API — Render

1. https://dashboard.render.com → **New → Blueprint** → connect `EasyOffice2026/Mudawwrah-website`.
   Render reads [`render.yaml`](render.yaml) and proposes the `mdawra-api` web service.
2. Fill in the env vars it marks as required:

   | Variable | Value |
   | --- | --- |
   | `DATABASE_URL` | the Supabase URI from step 1 |
   | `PUBLIC_URL` | `https://mdawra-api.onrender.com` (adjust if you rename the service) |
   | `CORS_ORIGINS` | `https://<your-project>.vercel.app` (fill in after step 3, then redeploy) |
   | `SEED_ADMIN_EMAIL` | your admin email |
   | `SEED_ADMIN_PASSWORD` | a strong password (do **not** keep `Admin@123`) |

   `JWT_SECRET` is generated by Render. The build runs `prisma migrate deploy`, so the schema is created automatically.
3. After the first successful deploy, load the menu once from the Render **Shell**:

   ```bash
   npm run db:seed
   ```

4. Check https://mdawra-api.onrender.com/api/health → `{"status":"ok"}`.

**Plan note:** `render.yaml` requests a 1 GB persistent disk at `/var/data/uploads` for admin image uploads,
which requires a paid instance type. On the free plan, delete the `disk:` block and the `UPLOAD_DIR` var —
the API still runs, but uploaded images are wiped on every deploy/restart (swap `mediaService` for S3/Cloudinary later).

---

## 3. Frontend — Vercel

1. https://vercel.com/new → import the same repo.
2. **Root Directory**: `frontend` (Vite is detected automatically; [`frontend/vercel.json`](frontend/vercel.json)
   adds the SPA rewrite so `/admin/...` deep links work).
3. Environment variable:

   | Variable | Value |
   | --- | --- |
   | `VITE_API_URL` | `https://mdawra-api.onrender.com/api` |

4. Deploy, then copy the resulting `https://<project>.vercel.app` URL into `CORS_ORIGINS` on Render and redeploy the API.

---

## 4. Verify

- Customer site: `https://<project>.vercel.app` — five menu sections load, prices show as `KWD 0.000`.
- Admin: `https://<project>.vercel.app/admin/login` — sign in with `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD`.
- Place a test order and confirm it appears in Admin → Orders.
- Settings → set your real WhatsApp number, delivery fee, minimum order, and the open/closed toggle.

## Custom domain

Add the domain in Vercel (site) and, optionally, a subdomain such as `api.mdawra.com` in Render;
if you do, update `PUBLIC_URL`, `CORS_ORIGINS`, and `VITE_API_URL` to match.
